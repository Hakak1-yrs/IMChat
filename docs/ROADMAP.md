- [x] 网络库：`Poller` 接口 + 基于 poll / WSAPoll 的实现、`EventLoop`（定时器、跨线程任务与唤醒）、`TcpServer`、`TcpConnection`（非阻塞收发、输出缓冲区、积压上限）

- [x] GoogleTest 单元测试和集成测试（30 个用例，乱序重复运行 900 次无失败）

- [x] 群消息推送、离线消息同步（分批）、已读回执
- [x] `TcpClient`（非阻塞连接、连接超时、指数退避重连）

- [x] 通用请求（`CALL_REQ`，操作名 → 处理函数的分发表）：联系人、群资料（含服务端计算的权限）、已读位置、撤回；好友在线状态推送、撤回推送、群消息带 @ 信息
- [x] 图形客户端联网模式：`Session` 抽象为接口（`LocalSession` / `RemoteSession`，桥接模式）。已经支持：
  - 会话列表、聊天、资料抽屉、未读、已读/未读、在线状态、@提醒、撤回；
  - 断线提示、"发送中"、重连补发、被挤下线回到登录页。
- [x] 图形客户端崩溃时记录调用栈（dbghelp），靠它定位并修复了一个临时对象生命周期的 bug

- [x] 好友功能联网：好友申请与验证、同意/拒绝（可设备注）、修改备注、单向删除、黑名单、好友资料页（服务端输出多态资料）。
  - 对方的操作通过 `DATA_CHANGED` 推送实时刷新；
  - 服务端改完好友数据立即写盘；
  - 好友资料页、新的朋友页改为只依赖 `Session` 接口，单机和联网共用同一套页面。

- [x] 群管理联网：建群/解散、全部群、申请与审批、邀请、踢人、管理员、禁言、公告、改名、转让、切换管理模式、讨论组。
  - 群操作封装成命令对象 `GroupCommand`（命令模式），由业务核心里的 `GroupService` 执行：单机模式本机执行，联网模式发给服务端执行同一个函数，群管理规则只有一份；
  - 群详情里查看者的权限由服务端按管理策略算好，客户端伪造请求也无法越权；
  - 操作产生的系统提示实时推给在线成员，被影响的人（包括被踢、被拒绝的人）收到 `DATA_CHANGED` 刷新。

- [x] 朋友圈联网：发表（四种可见范围）、点赞、评论与回复、删除、互动消息与红点。可见范围、只显示共同好友的互动等规则在服务端按查看者处理，别人动态的可见范围不下发。

- [x] 联网模式下一处登录、多个服务同时在线：服务端签发登录令牌（HMAC-SHA256 签名，密钥保存在数据目录，重启后仍有效）。
  - 客户端凭令牌登录本人的其他服务账号，每个服务一条连接；
  - 导航栏可以切换服务，其他服务的未读红点实时更新；
  - 断线重连也改用令牌，明文密码登录成功后就从内存里清除。

下一步：
- [x] `EpollPoller`：Linux 上默认使用，环境变量 `IMCHAT_POLLER=poll` 可以切回 poll 对比
- [x] 多线程：N 个 I/O 线程（one loop per thread）负责收发和解析，业务处理在单个业务线程里（不需要加锁），发件箱按 I/O 线程分批交回；私信吞吐提高 61%
- [ ] 业务状态分片到多个业务线程（群消息目前受限于单个业务线程）
- [x] 业务核心不再只依赖 Windows API：文件操作、编码转换、SHA-256 都有 POSIX 实现，服务端、命令行客户端、压测工具和全部测试可以在 Linux 上编译运行（在 MSVC、MinGW GCC、MSYS2 的 POSIX GCC 下验证）

原计划：

- **独立的 `IMChatServer`**，可以跨平台运行：Linux 上用 epoll，Windows 上用 WSAPoll，两者封装在同一个 `Poller` 接口下。
- **Reactor 线程模型**：一个 I/O 线程负责收发和分帧，业务逻辑交给工作线程池，结果再投递回 I/O 线程发送。
- **自定义协议**：`[4 字节长度][2 字节消息类型][JSON 正文]`。解码器负责处理半包和粘包，并限制单帧最大长度，防止恶意的超大长度把内存耗尽。
- **会话管理**：登录后服务端下发 token；心跳超时断开连接；客户端断线后自动重连，并补齐期间漏掉的消息。
- **消息可靠性**：
  - 客户端为每条消息生成 ID，服务端据此去重，这样客户端重发时不会出现重复消息。
  - 每个会话的消息按递增序号排序。
  - 服务端收到后回 ACK；对方离线时存为离线消息，上线后补发；支持已读回执。
- 现有业务类（账号、好友、群策略、朋友圈……）迁到服务端复用，控制台客户端和图形客户端只负责通信和显示。

## 阶段 2：存储

- [x] 消息存储接口 `MessageStore`（Repository），文本日志与 SQLite 两种实现，同一组一致性测试验证语义相同；以后接 MySQL 只需再加一个实现。
- [x] SQLite：表结构与索引、WAL、预编译语句缓存；同一轮事件循环的写入批量提交（先提交再发回执）；检查点移到后台线程，WAL 有界。
- [x] 迁移：第一次以 SQLite 启动时，把已有的 messages.txt 在一个事务里整体导入，序号、撤回、已读位置不变。
- [ ] 账号、好友、群也存进数据库（目前仍是文本文件，数据量小、写得少）。
